# ovh_email_domain_redirection

Manages an email address redirection on an OVHcloud email domain.

A redirection forwards mail sent to an address in the domain on to another address, which may be outside the domain. It
needs no mailbox on either side, so it works on domains with the redirect-only offer as well as on MX Plan ones.

## Example Usage

```terraform
resource "ovh_email_domain_redirection" "postmaster" {
  domain = "example.com"
  from   = "postmaster@example.com"
  to     = "admin@example.com"
}
```

Role addresses are a natural fit for `for_each`:

```terraform
variable "aliases" {
  type = map(string)
  default = {
    "postmaster" = "admin@example.com"
    "abuse"      = "admin@example.com"
    "sales"      = "someone.else@example.com"
  }
}

resource "ovh_email_domain_redirection" "aliases" {
  for_each = var.aliases

  domain = "example.com"
  from   = "${each.key}@example.com"
  to     = each.value
}
```

## Schema

### Required

- `domain` (String) Name of the email domain
- `from` (String) Address to redirect, which must belong to the domain
- `to` (String) Address to redirect to, which may be outside the domain

### Optional

- `local_copy` (Boolean) Whether to keep a copy in the source mailbox, which requires that mailbox to exist. Defaults to `false`. Set on creation only: the API never returns it, so its value is remembered from the configuration and a change forces a new redirection

### Read-Only

- `id` (String) Identifier of the redirection, assigned by OVHcloud

## Notes

`local_copy` is write-only. The API accepts it when the redirection is created but never returns it, so its value in
state is whatever was configured rather than anything read back. Changing it therefore forces a new redirection, and it
cannot be verified on import. Setting it to `true` requires a mailbox to exist at the `from` address, since that is where
the copy is kept.

Changing `to` goes through the dedicated `changeRedirection` endpoint rather than replacing the resource, but OVHcloud
assigns the result a **new id**. The resource looks the redirection up again afterwards, so this is handled, but do not
assume the id is stable across a target change.

Creating and updating return a task rather than the object, so the resource polls until the redirection is visible,
capped at two minutes.

## Import

A redirection can be imported using its `domain` and `id`, separated by a slash. The id is assigned by OVHcloud and can
be listed with `ovhcloud email-domain redirection list <domain>`, or from the API at
`GET /email/domain/{domain}/redirection`:

```bash
terraform import ovh_email_domain_redirection.postmaster example.com/123456789
```

`local_copy` is not part of what can be imported, so add it back to the configuration by hand if you use it.
