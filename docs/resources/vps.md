# ovh_vps

Orders and manages a VPS.

The attributes at the root hold the settings you requested for the VPS, and `current_state` holds what the VPS currently runs.

-> **NOTE** The schema of this resource changed in version 3.0.0 of the provider. The state is migrated automatically, but the configuration must be rewritten: see the [VPS migration guide](../guides/vps_migration).

## Important

-> **NOTE** Creating this resource places an order, which is billed. To order a product through Terraform, your account needs a default payment method. You can define it in the [OVHcloud Control Panel](https://www.ovh.com/manager/#/dedicated/billing/payment/method) or with the [/me/payment/method](https://api.ovh.com/console/#/me/payment/method~GET) API endpoint.

-> **NOTE** This resource is created through the OVHcloud order workflow and deleted through the termination workflow. If your consumer key has restricted access rules, it must allow the routes listed in [Consumer key access rules for resources that place orders](../guides/order_consumer_key_access_rules), in addition to `/vps/*`, `GET /me`, `GET /order/catalog/public/vps`, `GET /v2/location` and, to import a VPS, `GET /services` and `GET /services/*`.

~> **WARNING** `BANK_ACCOUNT` is not supported anymore, please update your default payment method to `SEPA_DIRECT_DEBIT`.

~> **WARNING** Changing `plan_code` or `location.region` from one value to another terminates the VPS and orders a new one. Check every plan that shows `ovh_vps` must be replaced.

## Example Usage

```terraform
resource "ovh_vps" "web" {
  plan_code = "vps-2025-model1"

  location = {
    region = "eu-west-gra"
  }

  installation = {
    from = {
      image_name = "Debian 12"
    }
  }
}

output "vps_ipv4" {
  value = [for address in ovh_vps.web.current_state.ip_addresses : address.ip if address.version == 4]
}
```

## Ordering a VPS

`terraform apply` orders the VPS with the subsidiary of your account and the default payment method, then waits for its delivery and its installation, for at most `timeouts.create` (60 minutes by default).

Before ordering, `terraform apply` checks in the order catalog that `plan_code` can be ordered in `location.region` with `installation.from.image_name`. When it cannot, the error lists the possible regions or images, and nothing is ordered.

`location.region` is an OVHcloud region code, such as `eu-west-gra`, among the regions of `GET /v2/location`.

`order.duration` and `order.pricing_mode` default to `P1M` and `default`. They must come from the same price, see [Choosing the plan, duration and pricing mode of an ordered product](../guides/order_plan).

This version of the provider does not support yet, when creating a VPS, the following settings. `terraform plan` refuses them, before any order:

- `installation.from.image_id`: set `installation.from.image_name`;
- `installation.ssh_key` and `installation.post_installation_script`;
- `installation.send_password_by_email = false`;
- `power_state` other than `ACTIVE`;
- `display_name`;
- `options.auto_backup.cron`.

### When the delivery takes longer than the timeout

The order is paid: it is kept in the state, in `order.order_id`, and `terraform apply` fails with `VPS order … is not delivered yet` or `VPS … is not ready yet`. Terraform then marks the resource as tainted, and the next `apply` would terminate it and order a new VPS. Run `terraform untaint` on it:

```sh
terraform untaint ovh_vps.web
```

The next `terraform plan` or `terraform apply` checks the delivery of the order once, without waiting. While the order is not delivered, it emits a warning and leaves the state as it is. Once it is delivered, it fills `id` and reads the VPS.

## Updating a VPS

This version of the provider does not update a VPS yet. `terraform apply` only records in the state, without calling the API:

- changes of `timeouts`, `order` and `installation.send_password_by_email`;
- values of `plan_code`, `location.region`, `power_state`, `installation.ssh_key` and `installation.post_installation_script` when the state has none, as after an import or the migration of the state.

Any other change, such as `display_name`, `power_state`, `installation` or `options`, is shown as an update in place by `terraform plan`, and `terraform apply` fails with `Updating a VPS is not supported yet`. Set these attributes back to their value in the state.

## Import

A VPS can be imported with its service name:

```sh
terraform import ovh_vps.web vps-1a2b3c4d.vps.ovh.net
```

Or with an `import` block:

```terraform
import {
  to = ovh_vps.web
  id = "vps-1a2b3c4d.vps.ovh.net"
}
```

The import reads `plan_code`, `order.duration` and `order.pricing_mode` from the billing of the VPS (`GET /services`), and the other attributes from the VPS. `installation.ssh_key` and `installation.post_installation_script` are never read back: their values in your configuration are recorded in the state.

~> **WARNING** Check the first `terraform plan` after an import: when `plan_code` or `location.region` in your configuration differ from the ones of the VPS, Terraform plans to replace it, which terminates it and orders a new one. Set them to the values of the state, shown by `terraform state show`.

## Reading a VPS

A VPS deleted outside Terraform is removed from the state: the next `terraform apply` orders a new one.

Reading a VPS whose service is expired fails, and the VPS stays in the state, so that Terraform does not order a new one. Renew the VPS, or remove it from the state with `terraform state rm`.

Reading the region of the VPS calls `GET /v2/location`. When your credentials are not allowed to call it, the read emits a warning that gives the reason, and `current_state.location.region` is null.

## Deleting a VPS

`terraform destroy` terminates the VPS. The provider asks for the termination, waits for the termination email for at most `timeouts.delete` (30 minutes by default), and confirms the termination with the token of the email.

A VPS whose order is not delivered yet cannot be terminated: run `terraform untaint` on it and wait for its delivery with `terraform apply`, or, if the order was cancelled, remove it from the state with `terraform state rm`.
