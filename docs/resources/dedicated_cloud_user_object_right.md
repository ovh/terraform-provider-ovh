# ovh_dedicated_cloud_user_object_right (Resource)

Manage a VMware on OVHcloud (dedicatedCloud/PCC) user's right on a single VMware object (cluster, datastore, dvportgroup, folder, pool or VM).

This is the object-level permission model used to build a least-privilege setup: grant/revoke access on individual VMware objects rather than on a whole datacenter.

~> The underlying API has no update endpoint for an object right: any change to `right`, `type`, `vmware_object_id` or `propagate` replaces the object right (delete + recreate).

-> The API's create response does not return the new right's id, so the provider resolves it by comparing the user's object rights before and after creation. Creates for the same `user_id` are therefore serialized by the provider. If an object right with the same `type`, `vmware_object_id` and `right` is added outside Terraform for that user while the create is running, the id cannot be resolved unambiguously and the create fails; import the right manually in that case.

## Example Usage

```terraform
resource "ovh_dedicated_cloud_user" "john" {
  service_name = "pcc-1-2-3-4"
  name         = "john.doe"
}

resource "ovh_dedicated_cloud_user_object_right" "john_cluster_readonly" {
  service_name     = ovh_dedicated_cloud_user.john.service_name
  user_id          = ovh_dedicated_cloud_user.john.user_id
  type             = "cluster"
  vmware_object_id = "domain-c1847"
  right            = "readonly"
  propagate        = true
}
```

## Schema

### Required

- `right` (String) User access on the VMware object
- `service_name` (String) The internal name of your VMware on OVHcloud
- `type` (String) Type of the object
- `user_id` (Number) Id of the user this right is granted to
- `vmware_object_id` (String) The VMware MoRef of the object

### Optional

- `propagate` (Boolean) Right propagation on children objects

### Read-Only

- `id` (String) Unique identifier for the resource
- `name` (String) Name of the VMware object
- `object_right_id` (Number) Id of the object right

## Import

A dedicated cloud user object right can be imported using the `service_name`, the `user_id` and the `object_right_id`, separated by "/" E.g.,

```bash
$ terraform import ovh_dedicated_cloud_user_object_right.john_cluster_readonly "<service_name>/<user_id>/<object_right_id>"
```
