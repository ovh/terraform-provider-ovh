# ovh_dedicated_server_virtual_mac

Attaches a virtual MAC address to an additional IP of a dedicated server.

A virtual MAC lets an additional IP be used behind its own network interface (for example a bridged virtual machine or a dedicated host interface): OVHcloud routes the IP only when traffic originates from the associated MAC. The MAC address itself is generated by OVHcloud and exposed as `mac_address`.

~> **NOTE** The virtual MAC is created together with its first IP. Destroying this resource removes the IP from the virtual MAC; OVHcloud releases the virtual MAC once its last IP is detached.

## Example Usage

```terraform
resource "ovh_dedicated_server_virtual_mac" "vmac" {
  service_name         = "nsxxxxxxx.ip-xx-xx-xx.eu"
  ip_address           = "1.2.3.4"
  type                 = "ovh"
  virtual_machine_name = "my-vm"
}
```

## Argument Reference

The following arguments are supported:

* `service_name` - (Required) The internal name of your dedicated server.
* `ip_address` - (Required) The additional IP address to attach to the virtual MAC.
* `virtual_machine_name` - (Required) A human-readable name to identify the IP/MAC pair.
* `type` - (Optional) The type of the virtual MAC address, `ovh` (default) or `vmware`.

## Attributes Reference

The following attributes are exported:

* `service_name` - See Argument Reference above.
* `ip_address` - See Argument Reference above.
* `virtual_machine_name` - See Argument Reference above.
* `type` - See Argument Reference above.
* `mac_address` - The virtual MAC address generated by OVHcloud.

## Import

A virtual MAC can be imported using the `service_name`, `mac_address` and `ip_address`, separated by "/" E.g.,

```bash
$ terraform import ovh_dedicated_server_virtual_mac.vmac service_name/mac_address/ip_address
```
