# ovh_email_domain_filter

Manages a filter on a mailbox of an OVHcloud email domain.

A filter tests the headers of incoming mail against its rules and, when **all** of them match, accepts the mail,
deletes it, redirects it, or moves it to another mailbox. A mailbox's filters apply in order of `priority`.

## Example Usage

```terraform
resource "ovh_email_domain_filter" "viruses" {
  domain       = "example.com"
  account_name = "john.doe"
  name         = "Delete viruses"
  priority     = 1
  action       = "delete"

  rules = [
    {
      header  = "X-Virus-Tag"
      operand = "contains"
      value   = "YES"
    },
  ]
}
```

Filters belong to a single mailbox, so applying one to every mailbox of a domain is a `for_each`. This one moves mail
that claims to come from the domain but failed DMARC into a quarantine mailbox:

```terraform
variable "mailboxes" {
  type    = set(string)
  default = ["alice", "bob", "carol"]
}

resource "ovh_email_domain_filter" "forged" {
  for_each = var.mailboxes

  domain       = "example.com"
  account_name = each.key
  name         = "Forged example.com"
  priority     = 2
  action       = "account"
  action_param = "quarantine@example.com"

  rules = [
    {
      header  = "From"
      operand = "contains"
      value   = "@example.com"
    },
    {
      header  = "Authentication-Results"
      operand = "contains"
      value   = "dmarc=fail"
    },
  ]
}
```

## Schema

### Required

- `account_name` (String) Mailbox the filter applies to, as the local part of its address
- `action` (String) What to do with matching mail: `accept`, `account` (move it to another mailbox), `delete` or `redirect`. There is no endpoint to change it, so a change forces a new filter
- `domain` (String) Name of the email domain
- `name` (String) Name of the filter, unique per mailbox. OVHcloud stores it lowercased and matches it case-insensitively, so a change of case alone is applied in place
- `priority` (Number) Order in which the mailbox's filters apply, lowest first
- `rules` (Attributes Set) Conditions on the mail's headers. **All** of them must match for the filter to apply, so they have no order (see [below for nested schema](#nestedatt--rules))

### Optional

- `action_param` (String) Full address the mail goes to, required by the `account` and `redirect` actions and refused by the others. A change forces a new filter
- `active` (Boolean) Whether the filter applies. Defaults to `true`

### Read-Only

- `id` (String) Identifier of the filter, `<domain>/<account_name>/<name>` with the name lowercased as OVHcloud stores it

### Nested Schema for `rules`

Required:

- `header` (String) Header to test, such as `From`, `Subject` or `Authentication-Results`
- `operand` (String) How to test it: `checkspf`, `contains` or `noContains`
- `value` (String) Value to test for

## Notes

Rules are **ANDed**: a filter applies only when every one of its rules matches, so they form a set with no order.

The creation call carries a single rule, and the others can only be added once the filter exists. Since a filter
holding only some of its rules matches more mail than intended, the resource creates it **inactive**, adds the other
rules, checks them, and only then activates it. When the rules of an existing filter change, the new ones are added
before the old ones are removed, so in between the filter matches only what both versions match. If a step fails once
the creation has been accepted, the filter is kept in state as tainted, so the next apply replaces it rather than
colliding with its name.

`action_param` must be a full address. The API accepts a bare local part such as `postmaster`, but resolves it against
OVHcloud's own mail host rather than the domain, so the matching mail would leave the domain. The resource refuses a
value without an `@`.

There is no endpoint to change `action` or `action_param`, so changing either replaces the filter. OVHcloud stores
names lowercased and matches them case-insensitively, so a change of case in `name` is applied in place.

Every change returns a task. The resource waits for its tasks to complete and for the result to show in the API, up to
ten minutes per step. The mail servers may take a few more minutes to apply it after that.

## Import

A filter can be imported using its `domain`, `account_name` and `name`, separated by slashes. The name comes last and
may contain spaces:

```bash
terraform import ovh_email_domain_filter.viruses 'example.com/john.doe/Delete viruses'
```
